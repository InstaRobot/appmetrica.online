# Open Questions: appmetrica.online

**Версия**: 1.0 | **Дата**: 2026-10-13

> Вопросы, которые не решились в discovery appmetrica.online и требуют ответа во время реализации.
> У каждого есть owner, срок (дата или эпик из [08-roadmap.md](./08-roadmap.md)), варианты, рекомендация
> и последствия, если решение не принято.
>
> **Критичное правило**: ни один open question не остаётся без решения или default. Всё, что не решено, записано здесь
> с явными метаданными, а у каждого вопроса есть **default** — решение, которое применяется, если к дедлайну
> ничего не выбрано. Owner всех вопросов — владелец (solo), внешние консультации указаны отдельно.
> Связанные риски — в [09-risks-and-mitigations.md](./09-risks-and-mitigations.md).

## 1. Must resolve before Epic N (blocker questions)

### OQ-001: Требует ли 152-ФЗ первичного хранения аналитики российских пользователей в РФ?

- **Категория**: Legal.
- **Почему открыт**: на интервью юриста не было. Неясно, являются ли `install_id` (случайный UUID), непрозрачный `user_id`,
  страна и город (из IP, сам IP не хранится) персональными данными в смысле 152-ФЗ, и распространяется ли на них ч. 5 ст. 18
  (локализация). Сервер стоит в Hetzner FSN1 (Германия). Связанный риск — R-002.
- **Варианты на столе**:
  1. Данные не являются ПД → оставляем как есть, обновляем политики конфиденциальности приложений.
  2. Являются ПД → отдельный ingest-узел в РФ (VPS Selectel) с собственным ClickHouse для событий российских пользователей
     и репликацией обезличенных агрегатов в ЕС. Около 2 недель работы.
  3. Являются ПД → не принимать события из РФ (отказ по стране). Неприемлемо по продукту.
- **Blocker для**: снятия AppMetrica SDK (M6) и запуска сверки M5 для приложений с долей пользователей из РФ больше 20 %.
- **Deadline**: 2026-12-04 (до конца сверки).
- **Owner**: владелец.
- **Консультации нужны от**: юриста по персональным данным (РФ), 1 консультация.
- **Рекомендация**: получить письменное мнение до 2026-12-04; до этого не снимать AppMetrica SDK из приложений с РФ-аудиторией.
- **Что если не решим**: default — вариант 1 с фиксацией принятого риска в R-002; AppMetrica SDK снимается только
  из приложений, где доля РФ меньше 20 % по отчёту «Аудитория → страна».

### OQ-002: Резервный домен для ingest (план Б по товарному знаку)

- **Категория**: Business / Legal.
- **Почему открыт**: владелец осознанно выбрал `appmetrica.online` (риск R-001), но имя резервного нейтрального домена не выбрано.
  Fallback URL должен быть вшит **с первого** релиза приложения, иначе старые версии останутся без плана Б.
- **Варианты на столе**:
  1. Зарегистрировать нейтральный домен под собственным брендом владельца (`.com` или `.dev`) с записью `i.<домен>` на тот же сервер.
     Клиенты получают два URL: основной и резервный (fallback при DNS-ошибке или TLS-ошибке домена).
  2. Не вшивать резерв; приложения с бэкендом берут URL из remote config.
  3. Не делать ничего (принять потерю старых версий при утрате домена).
- **Blocker для**: E9a / релиза iOS-приложения №1 (M2).
- **Deadline**: 2026-10-28 (до отправки iOS-приложения №1 на ревью).
- **Owner**: владелец.
- **Консультации нужны от**: не нужны.
- **Рекомендация**: вариант 1. Стоимость — 10–15 €/год, в Dokploy добавляется второй домен для Application `appmetrica-ingest`,
  рецепты доков сразу показывают fallback.
- **Что если не решим**: default — вариант 2 для приложений с бэкендом и вариант 3 для остальных. Риск R-001 остаётся High без смягчения.

### OQ-003: ECC-память — AX102-1 или ECC-вариант (AX102-3 / AX102-2)

- **Категория**: Technical / Infrastructure.
- **Почему открыт**: по документации Hetzner AX102-1 — 128 ГБ DDR5 без ECC, ECC-вариант там называется AX102-3,
  а в живом прайсе с ECC значится только AX102-2 (192 ГБ ECC, 547,30 €/мес). На странице продукта AX102 указано «DDR5 ECC».
  Источники противоречат друг другу.
- **Варианты на столе**:
  1. AX102-1 (257,30 €/мес + 129 € setup), ECC не гарантирован. ClickHouse хранит checksums партов, RAID1 и бэкапы в S3 защищают от потери.
  2. AX102-2 (547,30 €/мес + 274 € setup) с ECC: защита от тихой порчи данных в памяти.
  3. EX63-1 (147,30 €/мес, 64 ГБ ECC, 2×1 ТБ NVMe DC), но в RAID1 только около 0,93 ТиБ, впритык к требованию в 1 ТБ.
- **Blocker для**: E9a (заказ сервера 2026-10-26).
- **Deadline**: 2026-10-26.
- **Owner**: владелец.
- **Консультации нужны от**: Hetzner support — уточнить в форме заказа Robot, есть ли ECC у AX102-1.
- **Рекомендация**: вариант 1, если в форме заказа ECC указан; иначе тоже вариант 1. Для внутренней аналитики
  разница в 290 €/мес не оправдана, а checksums ClickHouse обнаруживают порчу партов при чтении и слиянии.
- **Что если не решим**: default — AX102-1 в FSN1 (если нет в наличии — HEL1).

## 2. Resolve during implementation (non-blocking, но нужно знать)

### OQ-010: Переход на Node.js 26 LTS

- **Категория**: Technical.
- **Контекст**: бутстрап закреплён на Node 24.21.0 LTS. 24.x уходит в maintenance 2026-10-20 (поддержка безопасностью до 2028-04-30),
  а Node 26.11.1 станет LTS 2026-10-28. В Node 25+ нет Corepack, поэтому pnpm ставится через `npm i -g pnpm@12.11.2` или `packageManager` + standalone-установщик.
- **Resolve when**: начало E5 (2026-11-09), после того как Node 26 станет LTS.
- **Варианты**: остаться на 24 до P1 / перейти в E5 / перейти после M4.
- **Owner**: владелец.
- **Default**: переход в E5 одним PR (`.nvmrc`, `engines`, базовый образ `node:26-alpine` с конкретным patch-тегом,
  CI-матрица), если Next.js 16.4 и fumadocs проходят `pnpm build` и Playwright на Node 26. Иначе — после M4.

### OQ-011: MSW 3.0.3 или 2.15.0 для моков, сгенерированных orval

- **Категория**: Technical.
- **Контекст**: orval 8.42.0 генерирует MSW-хендлеры с peer `msw >= 2`. MSW 3 вышел 2026-09-28 с breaking changes; совместимость не подтверждена.
- **Resolve when**: E0, тикет на настройку web-тестов (неделя 1).
- **Варианты**: msw 3.0.3 / msw 2.15.0.
- **Owner**: владелец (по результату smoke-теста агента).
- **Default**: msw 3.0.3; если smoke-тест «orval mock + vitest» падает — 2.15.0 с записью в ADR.

### OQ-012: Формат ежедневного дайджеста в Telegram

- **Категория**: Product.
- **Контекст**: решено, что дайджест — «портфель за вчера», но точная вёрстка сообщения не утверждена.
- **Resolve when**: E8 (2026-11-23).
- **Варианты**: моноширинная таблица в `<pre>` (HTML parse_mode) / список по приложениям с эмодзи-стрелками Δ / одна строка на приложение.
- **Owner**: владелец.
- **Default**: HTML parse_mode, по одной строке на активное приложение:
  `<b>Имя</b> · DAU 12 480 (▲4,1 % к пт) · новые 1 204 · сессии 31 022 · D1 38 %`, сверху дата и сумма DAU,
  снизу ссылка на портфель. Приложения отсортированы по DAU по убыванию. Максимум 30 строк, остальные — «и ещё N приложений».

### OQ-013: Срок хранения `job_runs`

- **Категория**: Technical.
- **Контекст**: якорь задаёт удаление `job_runs` старше 90 дней (job `session_cleanup`). Для разбора редких инцидентов может понадобиться больше.
- **Resolve when**: E8.
- **Owner**: владелец.
- **Default**: 90 дней. Записи `deletion` (журнал GDPR-удалений) хранятся в `deletion_requests` бессрочно, поэтому журнал удалений не теряется.

### OQ-014: Какое приложение становится «iOS-приложением №1» для сверки

- **Категория**: Product.
- **Контекст**: сверка (NFR-010) идёт на первом подключённом приложении. Нужно приложение, где AppMetrica уже стоит и стабильно работает.
- **Resolve when**: до E9a (2026-10-26).
- **Варианты**: приложение без логина с наибольшим DAU (чистое сравнение, `unit=persons` = `unit=installs`) /
  приложение с логином (проверяет склейку) / оба.
- **Owner**: владелец.
- **Default**: приложение без логина с наибольшим DAU; приложение с логином подключается вторым в E9b.

## 3. Nice to know (без dedicated owner)

### OQ-020: Нужен ли heartbeat для точной длительности сессий

- **Контекст**: длительность занижается при потере `session_end` (R-008). Heartbeat раз в 60 с отвергнут на интервью из-за объёма запросов.
- **Resolve when**: через 30 дней после M4, по доле сессий без `session_end` на экране аудитории.
- **Критерий**: если доля сессий без `session_end` больше 25 % в приложении, рассмотреть heartbeat только для него.
- **Что пока**: только `session_start` / `session_end` с персистентной очередью.

### OQ-021: Нужна ли мобильная вёрстка дашборда

- **Контекст**: решено «только десктоп, от 1280px». Дайджест в Telegram закрывает мобильный сценарий «глянуть цифры».
- **Resolve when**: через 3 месяца после M4.
- **Критерий**: владелец больше двух раз в неделю открывает дашборд с телефона (видно по `auth_sessions.user_agent`).

## 4. Technical debt accepted (сознательно)

### TD-001: Rate limiting в памяти одного процесса

- **Контекст**: лимиты per app и per install — `golang.org/x/time/rate` в памяти `appmetrica-ingest` (одна реплика).
- **Когда расплачиваемся**: при запуске двух и более реплик ingest лимиты поделятся между ними и станут неточными.
- **Estimate refactor**: около 2 дней (Redis или лимит на уровне шарда по `app_id`).

### TD-002: Только русский интерфейс без i18n

- **Контекст**: строки прямо в коде (решение интервью).
- **Когда расплачиваемся**: если дашборд понадобится англоязычному сотруднику.
- **Estimate refactor**: около 5 дней (next-intl, вынос строк).

### TD-003: Нет тёмной темы и адаптива

- **Контекст**: светлая тема в стиле AppMetrica, минимальная ширина 1280px.
- **Когда расплачиваемся**: при OQ-021 = да.
- **Estimate refactor**: тёмная тема около 2 дней (токены уже в CSS-переменных), адаптив около 5 дней.

### TD-004: Один сервер без HA

- **Контекст**: RPO 24 ч, RTO 4 ч, отказоустойчивость держится на клиентской очереди (R-003).
- **Когда расплачиваемся**: при требовании RTO меньше 1 ч или RPO меньше 1 ч.
- **Estimate refactor**: около 5 дней (второй сервер, реплика ClickHouse с Keeper, реплика PG).

### TD-005: Миграции выполняются при старте api

- **Контекст**: `MIGRATE_ON_START=true` вместо отдельного migration-job; совместимость обеспечивает правило expand/contract.
- **Когда расплачиваемся**: при необходимости тяжёлой миграции CH (мутация на часы): старт api будет ждать.
- **Estimate refactor**: около 1 дня (отдельное Dokploy Application `appmetrica-migrate` с запуском по деплою).

### TD-006: Гео-база вшита в образ ingest

- **Контекст**: mmdb DB-IP скачивается при CI-сборке; обновление — ежемесячная пересборка `geo-refresh.yml`.
- **Когда расплачиваемся**: если ежемесячный rebuild упадёт два месяца подряд, база устареет.
- **Estimate refactor**: около 1 дня (hot reload из volume + job в worker).

## 5. Research needed

### RQ-001: Совместимость object lock Hetzner Object Storage с ротацией clickhouse-backup

- **Context**: бакет `appmetrica-ch-backup` хочется защитить object lock от удаления (ransomware, ошибка оператора),
  но `BACKUPS_TO_KEEP_REMOTE=35` удаляет старые бэкапы.
- **How to resolve**: тест на отдельном бакете: object lock в режиме governance с retention 7 дней + clickhouse-backup 2.8.1 `delete remote`.
- **Owner**: владелец.
- **Deadline**: E9b (2026-11-24).
- **Default**: versioning включён, object lock выключен, lifecycle `NoncurrentDays=14`.

### RQ-002: Conditional UI passkey (autofill) — go-webauthn + @simplewebauthn/browser 14

- **Context**: вход по passkey через autofill поля (`BeginDiscoverableMediatedLogin` + `startAuthentication({useBrowserAutofill: true})`).
- **How**: прототип в E2 на Safari 26 / Chrome 140+, E2E с виртуальным аутентификатором Playwright.
- **Owner**: владелец.
- **Deadline**: E2 (2026-10-30).
- **Default**: если conditional UI нестабилен — только кнопка «Войти с passkey».

### RQ-003: Lightweight DELETE на ReplacingMergeTree с bloom-filter индексами в ClickHouse 26.8

- **Context**: GDPR-удаление по `install_id` и `user_id` в `events`; нужно убедиться, что удалённые строки не всплывают
  после слияния и что skip-индексы ускоряют поиск.
- **How**: интеграционный тест на testcontainers `clickhouse/clickhouse-server:26.8.25.14` + `EXPLAIN indexes=1`.
- **Owner**: владелец.
- **Deadline**: E6 (2026-11-18).

### RQ-004: Fumadocs за аутентификацией в Next.js 16.4 с Cache Components

- **Context**: страницы доков должны рендериться динамически (проверка сессии в `(docs)/layout.tsx`), без статической генерации и без `'use cache'`.
- **How**: прототип в E7; проверить, что `generateStaticParams` не нужен и что `/docs/*` без cookie редиректит.
- **Owner**: владелец.
- **Deadline**: E7 (2026-11-20).
