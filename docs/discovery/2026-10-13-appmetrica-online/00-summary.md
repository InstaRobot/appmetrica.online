# Саммари: appmetrica.online

> Короткий обзор проекта для быстрого ввода в контекст (1-2 страницы).
> Этот документ написан **простым языком** — его может прочитать человек без технического бэкграунда.
> Источник всех решений — discovery-интервью от 2026-10-13 (34 вопроса, 4 ресёрч-цикла).

## Что строим

**appmetrica.online** — собственная система аналитики приложений «без SDK» для **одного владельца портфеля приложений** (iOS, macOS, Android, веб-сайты, Telegram-боты и бэкенды), которая показывает аудиторию, сессии и retention всех продуктов на одном экране и заменяет Яндекс AppMetrica. Приложения отправляют события обычным HTTP-запросом по документированному API; сторонний закрытый код в сборку не попадает.

Почему это нужно владельцу (дословно из интервью — все четыре боли отмечены):
- **SDK в сборке**: сторонний закрытый код, его вес, обновления, privacy manifest / Data safety, риски модерации в сторах.
- **Зависимость от Яндекса**: данные у третьей стороны, надёжность сервиса (13.10.2026 все домены AppMetrica отдавали «технические неполадки»).
- **Нет единой картины**: сайты, боты и десктоп в AppMetrica не завести.
- **Сложность**: интерфейс перегружен, нужные цифры искать долго; нужен один экран с главным по всем приложениям.

## Для кого

- **Primary users**: единственный пользователь — владелец и разработчик приложений (solo). Владеет Go, TypeScript/React, Linux/Docker/ops; ClickHouse не знает — поэтому в пакете подробные runbook-и и тесты аналитического SQL на фикстурах. Смотрит дашборд только с десктопа.
- **Secondary stakeholders**: пользователи приложений владельца (субъекты данных по GDPR и 152-ФЗ — их `install_id`, `user_id`, страна и город); ревьюеры App Store и Google Play (privacy labels, Data safety — отказ от SDK упрощает декларации); AI-агент-реализатор, который пишет код по тикетам этого пакета.

## Core experience (2 минуты в продукте)

Утром владелец открывает `https://appmetrica.online` и входит по passkey (Face ID / Touch ID, без пароля). Первый экран — **портфель**: таблица всех приложений с колонками «DAU сегодня», «DAU вчера», «Δ к тому же дню прошлой недели», «Новые», «Сессии», «D1», «D7» и спарклайном за 30 дней. Клик по строке открывает приложение в стиле AppMetrica: KPI-карточки (активные, новые, сессии, средняя длительность), большой график, DAU/WAU/MAU, разбивки по версии, ОС, устройству, стране, городу и языку, вкладки Retention (дневные и недельные когорты), Realtime (кто активен прямо сейчас), Профили (поиск по `install_id` или `user_id`) и Интеграция. Новое приложение подключается за минуты: владелец создаёт его, получает публичный ключ `pk_…` и готовые сниппеты для curl, Swift, Kotlin, JavaScript и Go, отправляет первое событие и видит, как статус «ждём первое событие» становится зелёным. Каждое утро в Telegram приходит дайджест по портфелю, а если ломается диск, бэкап или приём событий — алерт.

## Must-have на MVP (4–6 недель, 10–15 часов в неделю владельца на ревью и интеграцию)

- **Приём событий** `POST https://i.appmetrica.online/v1/events`: системные события `session_start` / `session_end`, батч до 500 событий, идемпотентность через `insert_id`, коррекция неверных часов устройства через `sent_at`, досыл офлайн-очереди до 7 дней, явный ответ по каждому отклонённому событию (FR-001..FR-006).
- **Идентификация «install_id + user_id» с ретро-склейкой «первый владелец»**: метрики считаются по людям; сервисный режим `unit=installs` для сверки с AppMetrica (FR-007).
- **Портфель** — главная страница со всеми приложениями (FR-012).
- **Аудитория**: DAU/WAU/MAU, новые, сессии, длительность, разбивки, фильтры, сравнение периодов (FR-013).
- **Retention**: классический day-N (D0..D30) и недельный (W0..W12), определения как в AppMetrica (FR-014).
- **Realtime**, **Профили** с GDPR-удалением, **экран «Интеграция»** с причинами отказов (FR-015, FR-016, FR-017, FR-019).
- **Read API** `https://api.appmetrica.online/v1` с ключами `sk_…` и **документация API за логином** с рецептами для каждой платформы (FR-018, FR-023).
- **Вход по passkey** (FR-008), управление приложениями и ключами (FR-009..FR-011), настройки владельца (FR-025).
- **Telegram**: ежедневный дайджест (FR-020) и системные алерты + healthchecks.io dead-man switch (FR-021).
- **Закрытие дня и хранение**: сырые события 25 месяцев, дневные агрегаты бессрочно (FR-022); фильтр production/development (FR-024).
- **Критерий успеха MVP**: 14 дней параллельной работы с AppMetrica, расхождение DAU и новых ≤ 5 % каждый день, D1 ≤ 3 п.п., ноль дней простоя приёма — после этого AppMetrica SDK удаляется из приложений.

## Ключевые технологические решения

| Слой | Выбор | Почему |
|---|---|---|
| Язык | Go 1.27.2 (бэкенд) + TypeScript 6.0.3 (дашборд) | Go — один статический бинарник, предсказуемая память, хорош для приёма событий; TypeScript — дашборд и доки. Оба языка владелец уверенно ревьюит |
| Фреймворк | stdlib `net/http` + oapi-codegen 2.8 (strict server); Next.js 16.4 + React 19.3, Tailwind 4, shadcn/ui (Radix), Recharts, Fumadocs | OpenAPI-first: один контракт генерирует Go-сервер, TS-клиент (orval) и страницы документации |
| База данных | ClickHouse 26.8 LTS (события) + PostgreSQL 18.6 (метаданные) | ≈ 18 млн системных событий в месяц (~0,2 млрд строк в год) при 100k DAU и до 150 млн/мес (1–2 млрд строк в год) после добавления кастомных событий — Postgres упирается; ClickHouse сжимает и считает uniq по миллиардам строк за секунды |
| Hosting | Hetzner AX102-1 (FSN1, ЕС) + Dokploy ≥ 0.30.8, образы из GHCR, панель только через Tailscale | Пользователи в основном за рубежом, бюджет не ограничен, но один сервер = минимум ops; Dokploy выбран владельцем |
| Auth | Только passkey (WebAuthn, go-webauthn 0.18.2), восстановление одноразовой ссылкой из CLI | Единственный пользователь; защищённый от фишинга вход без пароля |
| Payments (если есть) | Нет | Внутренний инструмент, монетизации нет |

Подход к тестам: **TDD** (сначала падающий тест, потом код). Аналитический SQL проверяется на ClickHouse в testcontainers с фикстурами и заранее известными ответами.

## Бюджет на инфру

- MVP (первые 3 мес): ≈ 266 €/мес (≈ $290): сервер AX102-1 257,30 € + IPv4 1,70 € + Hetzner Object Storage 6,49 € (1 ТБ бэкапов включено); разово 129 € за установку сервера. Tailscale (личный тариф), healthchecks.io Hobbyist, GitHub Actions и GHCR — бесплатные тарифы; домен `appmetrica.online` уже есть.
- Растущий продукт (10k DAU): ≈ 266 €/мес (≈ $290) — тот же сервер рассчитан на 100k DAU и 25 месяцев хранения (≈ 210 ГБ ClickHouse при 1,92 ТБ полезного места). Рост расходов возможен только за Object Storage сверх 1 ТБ: ≈ 6,35 €/ТБ·мес.

## Что сознательно НЕ строим

- Кастомные события и отчёт по ним (API к ним готов без breaking change — P1), воронки, крэши, выручка, push, атрибуция рекламных трекеров.
- Импорт истории из AppMetrica — новая система пишет данные с нуля, обе работают параллельно.
- SDK для платформ — вместо них документация и рецепты (это и есть идея продукта).
- Тёмная тема, мобильная вёрстка дашборда (только десктоп от 1280px), i18n (только русский интерфейс).
- Мультипользовательский доступ, роли, приглашения — дашборд для одного человека.
- CSV-экспорт отчётов (P1), публичная документация и SEO-страницы.

## Ключевые риски

- **Товарный знак и домен**: «AppMetrica» — товарный знак Яндекса, а домен приёма вшивается в приложения; при UDRP-споре старые версии приложений перестанут отправлять данные. Риск принят владельцем осознанно; смягчение — отдельный поддомен `i.appmetrica.online`, URL в одной константе клиента, план миграции домена.
- **Один сервер**: отказ железа = простой до 4 часов и потеря до 24 часов данных (RPO 24 ч / RTO 4 ч); смягчение — RAID1, ежедневные инкрементальные бэкапы ClickHouse и Postgres в S3, runbook восстановления.
- **152-ФЗ и Dokploy**: данные пользователей из РФ хранятся в ЕС (открытый юридический вопрос); у Dokploy в 2026 были критические уязвимости — панель закрыта за Tailscale, обновления ручные.
