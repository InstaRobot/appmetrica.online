# Сверка с AppMetrica (NFR-010)

AppMetrica SDK убираем из приложений только после 14 дней параллельной работы, в которые наши цифры совпадают
с AppMetrica в пределах порогов:

| Метрика | Наш источник (Read API, `unit=installs`) | Порог |
|---|---|---|
| `active` — активные за день (DAU) | `getAudienceTimeseries?metric=active&granularity=day` | \|наши − AppMetrica\| / AppMetrica ≤ 5 % |
| `new` — новые за день | `getAudienceTimeseries?metric=new&granularity=day` | ≤ 5 % |
| `d1` — retention первого дня когорты дня | `getRetention?cohort_granularity=day&periods=1`, `values[1]` | \|наши − AppMetrica\| ≤ 3 п.п. |

Сверка идёт в режиме `unit=installs`: AppMetrica считает установки, а не склеенных по `user_id` людей. Плюс
14 дней подряд ни разу не должен сработать алерт `ingest_down` (S-12 «Настройки» → «Система», таблица
`alert_states`). Процедура — [22-test-strategy.md §11.3](../discovery/2026-10-13-appmetrica-online/22-test-strategy.md),
владелец — тикеты T-056 (запуск с 2026-11-28) и T-057 (вердикт 2026-12-11).

## Подготовка (один раз)

1. Приложение интегрировано по рецепту из `/docs/recipes`, AppMetrica SDK при этом остаётся в приложении.
2. Часовой пояс приложения в S-11 («Настройки приложения») совпадает с часовым поясом приложения в AppMetrica.
   Иначе дни разрежутся по-разному и расхождение будет на каждом дне.
3. В S-12 → «API-ключи» создан ключ `sk_` с правом `read` на это приложение, например с меткой «Сверка AppMetrica».
   Ключ передаётся только через переменную окружения `AM_SK`. В аргументы командной строки, URL и файлы
   репозитория он не попадает.
4. Запишите `app_id` приложения из адреса S-05 (`/apps/<app_id>/audience`).

## Экспорт из AppMetrica

Нужен один CSV с колонками дата, активные, новые и, если есть, retention первого дня:

```csv
Дата,Активные пользователи,Новые пользователи,Retention 1 день
2026-11-28,1000,200,40.0
2026-11-29,1000,180,
```

- Возьмите отчёт «Аудитория» с группировкой по дням и метриками «Активные пользователи» и «Новые пользователи»
  за весь период от первого дня сверки до вчера и выгрузите его в CSV.
- Из отчёта «Retention» (когорты по дням, «1 день») перенесите значения в колонку `Retention 1 день` в процентах.
  У когорты дня D значение появляется только на D+2, поэтому у вчерашнего дня ячейка пустая. Пустые D1 не
  сравниваются.
- Скрипт сам распознаёт формат:
  - разделитель — запятая, точка с запятой или табуляция;
  - BOM в начале файла;
  - даты `YYYY-MM-DD` и `ДД.ММ.ГГГГ`;
  - пробелы между разрядами (`1 234`), десятичную запятую и знак `%`;
  - строку «Итого», которая пропускается.
- Заголовки колонок принимаются в нескольких вариантах:
  - дата: `Дата`, `date`;
  - активные: `Активные пользователи`, `Активные`, `Пользователи`, `active`, `dau`;
  - новые: `Новые пользователи`, `Новые`, `new`;
  - D1: `Retention 1 день`, `Удержание 1 день`, `d1`.

  Если в выгрузке AppMetrica заголовок называется иначе, переименуйте колонку.

## Ежедневный запуск (10:00 MSK, за вчера)

```bash
export AM_SK=sk_…   # ключ из S-12, только read
d=$(date +%F)
make reconcile ARGS="-csv $HOME/Downloads/appmetrica-audience.csv \
  -api https://api.appmetrica.online/v1 -app <app_id> \
  -save docs/reconciliation/$d-snapshot.json" | tee docs/reconciliation/$d.md
```

Без make из каталога скрипта: `cd scripts/reconcile && go run . -csv … -api … -app …`.

Флаги:

| Флаг | Значение |
|---|---|
| `-csv` | экспорт AppMetrica (обязателен) |
| `-api` | базовый URL Read API (`https://api.appmetrica.online/v1`) или файл снимка, сохранённый через `-save` |
| `-app` | `app_id` приложения, нужен, если `-api` — URL |
| `-environment` | `production` (по умолчанию) или `development` |
| `-save` | сохранить ответы Read API в JSON, чтобы сверку можно было повторить без сети: `-api <файл>` |

Диапазон дат скрипт берёт из CSV. Он делает три запроса: `active`, `new` и retention, если в CSV есть D1.
Результат печатается markdown-таблицей, её удобно коммитить как `docs/reconciliation/<date>.md`:

```
| Дата | Метрика | Наши | AppMetrica | Расхождение | Итог |
|---|---|---|---|---|---|
| 2026-11-28 | active | 1049 | 1000 | +4.9 % | PASS |
| 2026-11-28 | new | 204 | 200 | +2.0 % | PASS |
| 2026-11-28 | d1 | 41.0 % | 40.0 % | +1.0 п.п. | PASS |
| 2026-11-29 | active | 949 | 1000 | −5.1 % | FAIL |
| 2026-11-29 | new | 175 | 180 | −2.8 % | PASS |

Пороги: active и new ≤ 5 %, d1 ≤ 3 п.п. (unit=installs).
Вердикт: FAIL — не прошли 1 из 5 проверок, дней: 2
```

Код выхода:
- `0` — все проверки прошли;
- `1` — хотя бы одна проверка не прошла;
- `2` — ошибка запуска, CSV или Read API: нет ключа, 401, нет колонки, плохая дата и т. п.

Пометки в колонке «Итог»:
- `FAIL: нет данных Read API` — у нас нет значения за этот день.
- `FAIL: AppMetrica = 0` — в AppMetrica ноль, а у нас нет, поэтому относительное расхождение не определено.

Снимок `-save` содержит только агрегаты (числа по дням) и коммитится вместе с таблицей.

## Вердикт после 14 дней

Сверка пройдена, если выполнены оба условия:

1. Есть 14 дней подряд, где у `active`, `new` и `d1` (где D1 уже известен) стоит PASS.
2. В эти дни ни разу не срабатывал `ingest_down`.

Если провален любой день, отсчёт 14 дней начинается заново со следующего дня после исправления. Итог записывается
в `docs/reconciliation/verdict.md` (T-057). После PASS AppMetrica SDK удаляется из приложений.

## Разбор расхождений больше порога

1. **Определение сессии.** Клиент шлёт `session_start` при каждом выходе на передний план, включая холодный
   старт (`/docs/concepts/sessions`). Если приложение пропускает `session_start`, у нас будет меньше `active`.
2. **Окружение.** События debug-сборок уходят с `environment = development`, а сверка идёт по `production`.
   Проверьте `-environment` и контекст батча в S-10.
3. **Часовой пояс приложения.** Он должен совпадать в S-11 и в AppMetrica (см. «Подготовка», п. 2).
4. **Отклонённые события.** Посмотрите S-10 «Интеграция» → отклонённые события за этот день: `event_too_old`,
   `install_rate_limited`, PII в `user_id`.
5. **Задержка доставки.** Офлайн-события приходят до 7 дней. Перезапустите сверку за этот день через 2–3 дня.
6. **Новые.** AppMetrica считает установку новой по первому запуску с SDK. Установки, у которых SDK стоял раньше,
   чем наша интеграция, в первые дни сверки у нас «новые», а у AppMetrica — нет. Начинайте 14-дневное окно не
   раньше чем через 7 дней после релиза с нашей интеграцией.

Если причина не найдена, заведите баг-тикет. К нему приложите таблицу и снимок за этот день, а в
`backend/testdata/fixtures/` добавьте фикстуру, воспроизводящую случай.
